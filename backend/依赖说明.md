go.mod 和 go.sum:
功能: 管理 Go 依赖项。go.mod 文件声明了模块的路径、Go 版本、以及项目所依赖的第三方库；go.sum 文件记录了所有依赖项的版本和校验。
注意点: 确保所有依赖项的版本和校验和在团队开发和 CI/CD 环境中是一致的，避免由于依赖版本不一致而导致的构建失败或运行错误。
难点: 当项目依赖项频繁更新时，维护这些依赖项版本和兼容性可能会变得复杂，尤其是在引入新的第三方库时，必须小心兼容性问题。

Dockerfile 和 Dockerfile.bundle:
功能: 定义如何构建 Docker 镜像。Dockerfile 用于基础镜像的构建，
Dockerfile.bundle 可能用于特定的环境或集成测试。
注意点: 确保 Docker 镜像的大小最小化，并且包含所有必要的依赖和环境配置。
使用多阶段构建来减少最终镜像的大小和攻击面。
难点: 当项目依赖复杂的构建工具链时，编写优化的 Dockerfile 可能很困难。
还要注意 Docker 缓存的使用和 Docker 镜像的安全性（如避免在镜像中存储敏感信息）。

.dockerignore:
功能: 列出不需要包含在 Docker 镜像中的文件和目录，通常包括不必要的开发文件（如日志、测试文件）或敏感数据。
注意点: 确保 .dockerignore 文件中的配置准确，以避免不必要的文件被添加到 Docker 镜像中，增加镜像的大小和构建时间。
难点: 确保 .dockerignore 文件的配置不遗漏重要文件，同时也不包含不需要的文件。


build.sh 和 entrypoint.sh:
功能: build.sh 用于自动化构建过程，包括依赖安装、代码编译、测试运行等；entrypoint.sh 是 Docker 容器的入口点，通常用于初始化环境或启动服务。
注意点: 确保 build.sh 和 entrypoint.sh 脚本的可移植性和健壮性，支持不同环境的构建和运行。确保脚本有适当的错误处理和退出码。
难点: 脚本的跨平台兼容性和错误处理可能会很复杂。必须处理好各种异常情况，如依赖缺失、编译错误或运行时错误。
development.md:

功能: 提供开发指南，描述如何在本地环境中设置和运行项目。
注意点: 文档需要详细和准确，确保新加入的开发人员能够快速上手。文档应定期更新，以反映项目的最新变化。
难点: 随着项目的更新和迭代，保持文档与代码一致可能会很困难。
